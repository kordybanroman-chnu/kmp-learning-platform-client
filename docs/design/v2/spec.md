# Learning Platform: специфікація UI, версія 2

Документ описує застосунок цілком: дані, правила, екрани, стани й токени. Макети до нього лежать у `preview.html`.

Версія 2 замінює макети Academic Precision з `docs/design/screens`. Причина заміни: старі макети показували дані, яких немає в API (коди курсів, семестри, ECTS, сертифікати, повернення коштів, факультет, ID студента), і мали надлишок рамок, насичених пігулок, банерів і шести кольорів статусів. Нова версія показує тільки те, що повертає сервер, і покладає ієрархію на картки, типографіку та один акцент.

Візуальна мова: світлий canvas, картки на surface з радіусом 16 і м'якою тінню, елементи керування з радіусом 12, іконки 20-22 px і статус-чіпи з м'яким фоном. Системна тема бере з платформи тільки ознаку «темно»; динамічні кольори Android і KDE не використовуються.

## 1. Джерело даних

Клієнт працює з сервісом Enrollments репозиторію `dotnet-learning-platform`, порт `5042`.

| Метод | Маршрут | Що повертає |
| --- | --- | --- |
| GET | `/api/courses` | список курсів |
| GET | `/api/courses/{id}` | один курс |
| GET | `/api/students` | список студентів |
| GET | `/api/students/{id}` | один студент |
| GET | `/api/enrollments?studentId={id}` | заявки студента без позицій і нотатки |
| GET | `/api/enrollments/{id}` | заявка з позиціями, нотаткою і графіком |
| POST | `/api/enrollments` | створює заявку зі статусом Submitted |
| POST | `/api/enrollments/{id}/confirm` | переводить заявку в SeatsConfirmed |
| POST | `/api/enrollments/{id}/cancel` | переводить заявку в Cancelled |

Помилки сервер віддає у форматі ProblemDetails: `title`, `status`, `detail`, `traceId`. `detail` англійською, тому клієнт не показує його користувачу, а перекладає код статусу у власне повідомлення (розділ 3.7).

Базову адресу задає користувач у налаштуваннях. Значення за замовчуванням: `http://localhost:5042` для десктопа і `http://10.0.2.2:5042` для емулятора Android.

### 1.1 Чого в API немає

Цих полів не можна показувати, навіть як заглушку:

- опису, зображень, категорій, викладачів, рейтингів і відгуків курсу;
- кількості кредитів ECTS, семестру, коду дисципліни;
- дат зміни статусу, історії статусів;
- сертифікатів, повернень коштів, оцінок;
- посади, факультету, номера студентського квитка;
- пошуку, фільтрів і сортування на сервері.

## 2. Модель даних

```
Course         id, title, price, seatsAvailable
Student        id, email, fullName
Enrollment     id, studentId, status, enrolledAt, note?, preferredSchedule?, items[]
EnrollmentItem courseId, courseTitle, unitPrice, units
```

Правила, які впливають на UI:

1. `units` - кількість місць у позиції. Сума позиції: `unitPrice × units`. Сума заявки: сума всіх позицій.
2. `price` у курсі і `unitPrice` у позиції - ціна за одне місце, не за весь курс.
3. `GET /api/enrollments?studentId=` не повертає `items`, `note` і `preferredSchedule`. Тому список заявок показує тільки номер, дату і статус. Курси й суму показує екран деталей, який робить окремий запит.
4. `enrolledAt` приходить у ISO 8601. Показуємо як `дд.ММ.рррр` локального часу.
5. `note` до 1000 символів, `preferredSchedule` до 200, `units` від 1 до 1000. Обмеження перевіряються і на клієнті, і на сервері.
6. Одна заявка не може містити той самий курс двічі: пара `(EnrollmentId, CourseId)` є первинним ключем.

## 3. Загальні правила

### 3.1 Поточний студент

Авторизації немає. Студента вибирають у налаштуваннях зі списку `/api/students`, вибір зберігається на пристрої разом з ім'ям. Ідентифікатор використовується в усіх заявках.

- Якщо збереженого студента немає, після першого завантаження списку вибирається перший студент і зберігається.
- Ім'я поточного студента показується на екрані «Мої заявки» і на формі нової заявки.
- Зміна студента перезавантажує список заявок.
- Якщо список студентів не завантажився і збереженого студента немає, форма нової заявки недоступна: кнопка «Подати заявку» вимкнена з підказкою «Виберіть студента в налаштуваннях».

### 3.2 Статуси

| Статус у API | Підпис | Коли трапляється |
| --- | --- | --- |
| Submitted | Подано | одразу після створення |
| AwaitingValidation | На перевірці | сервер перевіряє заявку |
| SeatsConfirmed | Місця підтверджено | після `confirm` |
| Paid | Оплачено | оплата пройшла |
| Completed | Завершено | курс закінчено |
| Cancelled | Скасовано | після `cancel` |

Переходи, які робить клієнт:

- `confirm` дозволений сервером тільки зі статусів Submitted і AwaitingValidation, за наявності позицій і вільних місць. Кнопка «Підтвердити місця» показується тільки для цих двох статусів.
- `cancel` дозволений сервером для всіх статусів, крім Paid, Completed і Cancelled. Для SeatsConfirmed сервер повертає місця в каталог. Кнопка «Скасувати заявку» показується для Submitted, AwaitingValidation і SeatsConfirmed.
- Після успішного `confirm` або `cancel` екран деталей повторно читає заявку через `GET /api/enrollments/{id}`. Якщо повторне читання не вдалося, показуємо останній відомий стан і банер «Статус може бути неактуальним» з кнопкою «Оновити».

### 3.3 Гроші

- Формат `uk`: `1 200,00 ₴`, розділювач тисяч - нерозривний пробіл, десятковий - кома, символ валюти після числа.
- Формат `en`: `UAH 1,200.00`.
- Цифри табличні (`font-variant-numeric: tabular-nums`), щоб суми в списку стояли одна під одною.
- Сума обчислюється на клієнті для форми і для екрана деталей. Сервер окремого поля `total` не має.
- Показуємо завжди два знаки після коми, навіть якщо сервер повернув `1200` або `1200.0`.

### 3.4 Дати

`дд.ММ.рррр`, без часу. Час `enrolledAt` не показуємо: для заявки достатньо дати.

### 3.5 Мова

Українська і англійська. Мова інтерфейсу зберігається на пристрої. Назви курсів, нотатки й графік є даними сервера, тому не перекладаються. В англійському інтерфейсі назва курсу лишається тою, що повернув сервер.

### 3.6 Тема

Світла, темна і системна. Системна бере з платформи тільки ознаку «темно», а кольори завжди з палітри застосунку. Динамічні кольори Material You і палітра KDE у версії 2 не використовуються: вони додають довільний акцент до системи з одним акцентом.

### 3.7 Помилки

| Подія | Що показуємо |
| --- | --- |
| Немає мережі, таймаут | банер «Немає зв'язку із сервером» + «Повторити» |
| 400 від POST | підписи під полями: «Перевірте кількість місць» |
| 404 заявки | екран «Заявку не знайдено» + «До списку» |
| 404 курсу | екран «Курс не знайдено» + «До каталогу» |
| 409 на confirm | «Вільних місць уже немає. Скасуйте заявку і створіть нову.» |
| 409 на cancel | «Цю заявку вже не можна скасувати.» + повторне читання |
| 500 | «Помилка сервера. Спробуйте пізніше.» |
| Некоректна адреса сервера | «Адреса має починатися з http:// або https://» |

Текст `detail` з ProblemDetails не показуємо ніколи: він англійський і містить внутрішні назви полів.

### 3.8 Стани екранів

Кожен екран з мережевими даними має чотири стани: завантаження, дані, порожньо, помилка.

- Завантаження: три статичні рядки-заглушки з лініями, без анімації й спінерів.
- Порожньо: один рядок тексту і дія, якщо вона є (наприклад, «До каталогу»).
- Помилка: текст і кнопка «Повторити», без автоматичних повторів.
- Дані лишаються на екрані під час повторного завантаження; замінювати їх заглушкою не потрібно.

### 3.9 Доступність

- Мінімальна площа натискання 48×48 dp; візуальна висота кнопки 44-48 dp, рядка списку 70 dp.
- Статус завжди має текстовий підпис, колір лише доповнює його.
- Контраст тексту до фону не нижче 4.5:1.
- Кнопки кроку мають підписи «Додати місце» і «Зменшити кількість».
- Рядок каталогу озвучується як «Курс Основи C#, 1 200 гривень, 30 місць».
- Фокус на десктопі: рамка 2 px акцентом і м'яке кільце 3 px кольором accent-soft.
- Клавіатура: Tab обходить елементи зверху вниз, Enter підтверджує форму, Esc закриває діалог.

### 3.10 Платформи

- Android: нижня навігація, системна кнопка «Назад» веде на попередній екран, safe insets зверху і знизу, ширина від 360 dp.
- Desktop: вікно від 900×600, ліва навігація 240 px, контент до 1040 px, сітка з трьох карток, рядки таблиць 56 px, hover для рядків і кнопок.
- Спільні екрани, стилі й логіка лежать у `shared`, платформи відрізняються тільки навігаційною оболонкою.

### 5.4 Нова заявка

Призначення: зібрати курси, кількість місць, нотатку і графік та надіслати заявку.

Склад:

- вибраний курс розгортає рядок «Місця» зі степпером `− 1 +` (кнопки 30×30) і сумою позиції праворуч;
- курс без місць вимкнений, чекбокс сірий, у метаданих «місць немає»;
- секція «Деталі»: картка з полем «Нотатка» (textarea 80 px) і полем «Бажаний графік» (48 px), підписи 12/16;
- внизу липка панель оформлення: «Разом» 11/14, сума 20/26 зліва, кнопка «Подати заявку» 44 px справа.

Підказка «Місця резервуються після підтвердження» не дублюється на формі: вона є на екрані деталей курсу і в кроці 2 блока «Як це працює».

Правила:

1. Курс можна вибрати тільки якщо `seatsAvailable > 0`.
2. `units` від 1 до `min(seatsAvailable, 1000)`. Кнопка «−» вимкнена на 1, «+» на межі.
3. Порожня нотатка і порожній графік надсилаються як `null`, а не як порожній рядок.
4. Кнопка «Подати заявку» вимкнена, поки не вибрано жодного курсу або не вибрано студента.
5. Під час надсилання кнопка показує «Надсилання…», поля й кнопки вимкнені.
6. Успіх: `POST /api/enrollments` повертає заявку, відкривається її екран деталей з повідомленням «Заявку подано».
7. Помилка: банер над панеллю оформлення, введені дані не губляться.
8. Вихід із заповненої форми (кнопка «Назад» або системна кнопка Android) показує діалог «Відкинути зміни?» з кнопками «Відкинути» і «Продовжити».
9. Якщо курс відкрито з деталей, він уже вибраний з `units = 1`.

Порядок полів у запиті:

```json
{
  "studentId": 1,
  "items": [{ "courseId": 101, "units": 1 }],
  "note": "Вечірня група",
  "preferredSchedule": "Пн/Ср 19:00"
}
```

Desktop: та сама форма в колонці 640 px. Степпер і чекбокси працюють з клавіатури.

| Статус | Заголовок картки | Текст |
| --- | --- | --- |
| Submitted | Заявку подано | Місця резервуються після підтвердження. |

| Completed | Курс завершено | Заявка закрита. |

Трек статусу:

- пройдений крок: круг 20 px із заливкою акцентом і білою галочкою;
- поточний крок: круг 20 px з рамкою акцентом і точкою 8 px всередині, підпис основним кольором;
- майбутній крок: порожній круг з рамкою border-strong, підпис низьким кольором;

Дії:

| Статус | Кнопки |
| --- | --- |
| Submitted, AwaitingValidation | «Підтвердити місця» (основна), «Скасувати заявку» (текстова, небезпечна) |
| SeatsConfirmed | «Скасувати заявку» (контурна, небезпечна) |
| Paid, Completed | немає |
| Cancelled | немає дій зі статусом; внизу «До каталогу» (навігація) |

Підтвердження:

- «Підтвердити місця» викликає `POST /confirm` без діалогу.

## 8. Що не входить

- Авторизація і профіль (лабораторна 5).
- Пошук, фільтри, сортування, пагінація.
- Редагування заявки після створення: API не має `PUT`/`PATCH`.
- Оплата: статус Paid виставляє сервер, клієнт його тільки показує.
- Push-повідомлення й фонове оновлення статусів.
- Завантаження файлів, аватари, зображення.
- Повторне подання скасованої заявки однією кнопкою: нову заявку створюють із каталогу.
- Динамічні кольори Material You і KDE.

## 9. Критерії приймання

1. У жодному екрані немає полів, яких немає в API (розділ 1.1).
2. Усі шість статусів мають підпис і чіп; Cancelled не показує трек кроків.
3. «Підтвердити місця» видно тільки для Submitted і AwaitingValidation.
4. «Скасувати заявку» не видно для Paid, Completed і Cancelled.
5. Після confirm або cancel екран читає заявку заново.
6. Сума на формі дорівнює сумі позицій, а не ціні курсів без множення на `units`.
7. Список заявок не робить запит деталей на кожен рядок.
8. Форма не дає вибрати курс без місць і не дає поставити `units` більше за місця.
9. Онбординг: 4 слайди, «Пропустити», «Далі», «Почати», індикатор, збереження прапорця.
10. Тема, мова і студент зберігаються між запусками.
11. Обидві теми проходять контраст 4.5:1 для тексту, включно з текстом статус-чіпів.
12. Екран працює від 360 px ширини без горизонтальної прокрутки.
13. Десктоп від 900×600: ліва панель 240 px, сітка карток, таблиця, hover і фокус з клавіатури.
14. Усі тексти є в `values/strings.xml` і `values-en/strings.xml`; назви курсів не перекладаються.
15. Кожна картка має рамку 1 px, тінь не є єдиним способом відділення; у темній темі тіней немає.
